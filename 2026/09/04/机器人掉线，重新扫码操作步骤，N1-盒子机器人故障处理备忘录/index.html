整套环境：Armbian + PM2 + n1.sh 自愈脚本 + systemd 开机守护

⚠️重要区分：

脚本只负责进程崩溃自动拉起；
账号会话风控、Cookie 过期、QQ 要求扫码，属于业务层面掉线，脚本无法自动修复，需要人工操作

🔍快速判断故障命令

📌场景 1：go‑cqhttp 掉线，需要 QQ 扫码登录

1，停止 pm2 内的 go‑cqhttp

2，前台临时运行，仅用来扫码登录（登录成功后必须 Ctrl+C 退出，不能长期前台跑）

终端输出字符二维码；如果二维码乱码，下载目录下 qrcode.png 到电脑打开扫码
扫码，看到【登录成功】，QQ 机器人可以正常收发消息

3，Ctrl + C 终止前台程序

4，pm2 后台托管启动

5，✅必做！保存状态，断电开机才能自动恢复

⚠️不要删除目录文件：session.token（登录会话）、device.json（虚拟设备），保留可以减少重复扫码。

📌场景 2：xdd 掉线（无二维码，cookie/token 凭证过期）

1，停止 xdd

2，修改 xdd 配置文件，填入最新 cookie / 账号凭证

3，前台测试运行，确认功能正常

4，Ctrl + C 退出前台程序

5，pm2 托管启动

📌场景 3：sillyGirl 掉线

✅修复完成后统一校验（每次处理完都跑一遍）

正常输出示例：

💾更新系统备份（修复正常后建议执行）

🚩开机服务查看命令（重启排错）

⚠️避坑重点（一定要记住）

  1. 禁止长期前台执行 ./go‑cqhttp、./xdd，前台运行脱离 PM2 管理，重启机器直接丢失；前台只用来登录调试。
  2. 每次新增 / 重建 pm2 进程，确认业务正常后，必须执行 pm2 save，否则开机不会自动拉起。
  3. QQ 风控导致 session.token 失效，无解，只能重新扫码；这是腾讯限制，脚本不能绕过。
  4. 升级 node 版本之后，需要修改n1‑host‑pm2‑restore.service内 pm2 的绝对路径。
